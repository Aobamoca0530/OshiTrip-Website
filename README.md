# OshiTrip 🧳✨

让每一次跑活，都能多遇见一点喜欢。

OshiTrip 是一个面向日本 IP 联动活动与跑活旅行的查询网站。你可以根据自己的出行日期、停留城市和喜欢的 IP，筛选旅途中可以顺便参加的活动，把想去的地方加入旅行备选。

## 🚀 下载与开始使用

文档更新：**2026-10-29**。当前正式应用版本为 **1.6.0**，见 [Release 说明](https://github.com/Aobamoca0530/OshiTrip-Website/releases/tag/v1.6.0)。[最新下载入口](https://github.com/Aobamoca0530/OshiTrip-Website/releases/latest)会指向后续正式版本。

普通使用无需安装 Node.js，也无需数据库账号或 AI API Key。按设备选择：

| 设备 | 获取方式 | 首次使用 |
| --- | --- | --- |
| Windows 10/11 x64 | Release 的 `OshiTrip-1.6.0-windows-x64.zip` | 完整解压到可写文件夹，双击 `OshiTrip.exe`，等待浏览器打开 |
| Android 7.0 及以上 | Release 的签名 APK | 允许下载 APK 的浏览器安装应用，完成安装后打开；需要现代 Android System WebView |
| iPhone / iPad | [OshiTrip 手机版](https://aobamoca0530.github.io/OshiTrip-Website/) | Safari 打开，选择「分享 → 添加到主屏幕」；首次联网等待「已可离线使用」 |
| Mac（macOS 13.5 及以上） | Release 的 `macos-arm64` 或 `macos-x64` ZIP | Apple Silicon 选 arm64，Intel 选 x64；解压后把 `OshiTrip.app` 拖入「应用程序」并打开 |

下载页的 **Assets** 中选择对应安装包；`Source code` 是源码，供下方开发环境安装使用。

Windows 请保留 EXE 旁边的文件夹，不要只复制 EXE，也不要直接在压缩包内运行。桌面版需要保持启动器运行，关闭启动器会停止本地服务；下次再次打开启动器即可。Windows 包尚未代码签名，Mac 包尚未进行 Apple Developer ID 签名和公证，Mac 首次运行可能需在「系统设置 → 隐私与安全性」允许打开。

### 第一次打开后怎么用

1. **设置偏好**：在「收藏与关注」选择喜欢的 IP。关注父系列会包含旗下子系列；只关注某个子系列时不会自动包含其他子系列。
2. **建立行程**：进入「我的旅行」，填写旅行起止日期，添加每座城市的停留日期，点击「保存旅行计划」。可另外添加自己的 Live、住宿等私人安排。
3. **寻找活动**：在「发现活动」按城市、日期、IP 和参加方式筛选。打开详情，核对具体门店的举办日期和预约规则；收藏整项活动，或把想去的门店加入旅行备选。
4. **查看 Live 与附券商品**：进入导航中的「抽选与发售」，查看演出报名、商品版本、抽选期限与店铺特典。已截止的附券先行和当前一般售票是不同轮次，请分别核对。
5. **跟进新公告**：在「官方新消息」查看 Live、线下活动及商品、菜单、特典配图。待审核内容可浏览，但不会直接进入正式行程匹配；页脚「来源状态与待审核」可查看资料的采集状态。

加入旅行备选不代表已预约或已安排具体日期。页面中的活动和报名时间按日本时间展示；出发、购买和预约前请打开官方链接确认。

### 旧版本怎么升级

| 要更新的内容 | 操作 | 需要注意 |
| --- | --- | --- |
| 活动、门店、商品与官方公告 | 联网启动，或点击「刷新活动数据」 | 同步维护者已发布的资料，不会现场抓取官网，也不升级软件功能 |
| Windows / Mac 程序 | 关闭旧启动器，从 Release 下载对应新版，完整解压后启动 | 保留原浏览器、浏览器资料和访问地址；Windows 端口暂时被占用时可能使用临时地址 |
| Android 程序 | 下载同签名新版 APK，直接覆盖安装 | 不要先卸载或清除应用数据 |
| iPhone / 手机网页版 | 联网打开，页面资源准备好后点击「立即更新页面」 | 先保存正在编辑的旅行计划；新资源不会自动刷新正在编辑的页面 |
| 源码版 | 更新源码，安装锁定依赖；生产模式重新构建、启动 | 源码、程序版本和公共资料分别更新，步骤见下方 |

1.6.0 起，启动时会检查软件新版，也可点击「检查软件更新」。发现新版后可查看说明与下载入口，或选择稍后。1.5.0 及更早启动包需要先手动升级一次。更新检查失败不影响继续使用已有资料；不会静默安装，也不会在关闭应用后推送通知。

**收藏与行程保存在哪里？** 保存在当前设备的应用或浏览器中，尚未跨设备同步。桌面版的浏览器、用户配置和完整访问地址（含端口）需要保持一致；Android 与 iPhone 的数据也各自独立。换设备、清理浏览器数据、清除应用数据或卸载可能丢失私人安排。活动资料缓存与私人收藏是两份不同的数据。

### 常见问题

- **没有近期活动**：先清除过窄的筛选条件，检查城市停留日期和「只看已关注 IP」，也可勾选「包含历史活动」。没有结果不代表官方没有举办活动。
- **更新资料后没有新功能**：资料更新只同步内容；页面或程序的新功能需要升级应用。最新源码也可能包含尚未打包的改动，以对应 Release 说明为准。
- **离线能做什么**：已安装的客户端可使用内置或已缓存的文字资料进行查询、收藏和规划；iPhone 网页版需先完成首次联网缓存。官方图片、地图与原文链接仍需联网。
- **收藏突然不见了**：先核对是否使用原应用、原浏览器用户配置和原访问地址。Windows 临时端口变化时，关闭占用原端口的自己的服务后重新启动，或等原端口空闲后再试；不要先清理浏览器数据。
- **官方消息仍显示待审核或来源过期**：刷新只下载已发布快照，不会自动通过审核。来源失败时保留旧资料；图中文字也可能仍待单独核实。

## 💭 为什么做这个网站

每次计划去日本跑活，我都会花很多时间翻官方 SNS。活动消息大多通过社交平台发布，联动咖啡、快闪店、展览、Live 和周边贩售的信息散落在不同账号和公告里，想整理出一份完整的行程并不方便。

看到感兴趣的活动后，往往还要继续查：活动在哪家店举办？我去的那几天还在不在？能直接入场，还是需要提前预约或参加抽选？不同门店的举办时间和参加规则是不是一样？

这些信息有时藏在长长的公告里，有时写在宣传图上，还有一些需要跳转到其他页面才能确认。等到好不容易查清楚，才发现活动和自己的行程对不上，或者已经错过了预约时间。

所以，我做了 OshiTrip，希望把散落的活动信息整理到一起，让跑活前的准备更方便。

## 🗺️ 它能帮你做什么

- **根据行程找活动**：按各个城市的停留日期匹配活动门店，看看旅途中有哪些可以顺路参加的活动。
- **围绕喜欢的 IP 筛选**：查找感兴趣的作品、企划和乐队相关活动，关注 IP、收藏想去的活动。
- **查看参加方式和预约信息**：集中查看举办时间、地点、预约或抽选安排，并通过官方链接确认具体规则。
- **整理旅行备选**：把感兴趣的活动放进行程备选，结合自己的私人安排规划跑活路线。
- **查询 Live 抽选关联商品**：了解附券商品、抽选时间和店铺特典，方便一起做出行准备。
- **自动发现公告与商品图**：在“官方新消息”查看自动采集的快闪、联动公告，以及现场售卖商品、菜单和特典图片。

比如，已经决定某几天在东京、之后去大阪，就可以按这段行程寻找同期举办的联动活动，再确认哪些需要提前预约、哪些适合安排在空闲时间。

## 💖 希望带来的改变

做这个网站的初衷很简单：少花一些时间反复翻 SNS、找公告和核对日期，多留一些时间给真正想参加的活动。

希望 OshiTrip 能帮你在已经确定的旅行里，找到那些“原来这次也能顺便去”的惊喜。

## 📌 最新资料与维护方式

活动资料包含官方出处和核实时间，收录范围仍在完善，不代表实时库存、预约名额或所有官方消息。未知信息继续标为未知。

截至本次文档更新，源码已包含按 IP 分组的 Live 报名与附券商品、官方演出与票务配图、来源状态面板，以及每日采集、翻译、独立复核和发现活动发布流程。**应用版本是 1.6.0，维护流程版本是 1.4.0**，两者用途不同。后续源码改动不会通过资料刷新自动安装到已有启动包中。

仓库的 `.github/workflows/public-data.yml` 计划在每天北京时间 **22:00** 运行，GitHub 调度可能延迟。云端运行不依赖用户电脑开机；配置了相应密钥时执行模型翻译和复核，未配置或调用失败的内容保留待办。普通用户无需配置密钥。

资料通过「官方正文与配图 → 中文翻译 → 独立审核 → 证据校验 → 发现活动 → 统一数据发布」更新。通过审核的活动可关联多张官方图片，但收录图片不等于图中文字全部审核；无法读取、模糊或冲突的信息保留待审核。虹咲新闻已接入浏览器辅助采集，官方 X 账号仅提供跳转入口，不自动同步帖子。实际覆盖范围与本轮结果请查看来源状态。

维护者请在 `oshitrip/` 中使用统一入口：

```sh
pnpm maintain:public                  # 采集并在本地生成、校验资料
pnpm maintain:public --publish        # 全部检查通过后提交、推送并确认远端
pnpm maintain:public --replay          # 使用已有采集快照应用复核，不重新联网采集
```

首次运行采集需安装 Playwright 浏览器，发布还需已配置的 Git 推送权限及符合要求的工作区。完整前置条件、AI 配置和图片复核步骤见[应用配置](oshitrip/README.md#每日自动采集)与[官方消息维护流程](oshitrip/docs/official-news-workflow.md)。手工资料修改见[统一数据发布步骤](oshitrip/README.md#统一数据发布步骤)。

## 🛠️ 从源码运行

应用源码位于 `oshitrip/`，需要 Node.js 24 与 pnpm 11.25.0。

```sh
cd oshitrip
pnpm install --frozen-lockfile
pnpm dev
```

默认使用本地活动资料，无需配置数据库账号即可运行。

### 🤖 AI 辅助本地部署（新手推荐）

想在自己的电脑上使用 OshiTrip，可以让 AI 帮你完成环境检查和启动。这里运行的是本地版，通过浏览器访问；无需购买服务器，也无需配置数据库或 AI API Key。首次安装依赖需要联网，官方图片、地图和外部链接也需要网络。

**第一步：下载项目**

在本仓库页面选择 **Code → Download ZIP**，解压到自己方便找到的位置；如果已经安装 Git，也可以运行：

```sh
git clone https://github.com/Aobamoca0530/OshiTrip-Website.git
```

下载后，打开项目最外层文件夹。真正的应用目录是里面的 `oshitrip/`，其中应有 `package.json` 和 `pnpm-lock.yaml`。

**第二步：把下面这段话复制给 AI**

让能访问本地文件和终端的 AI 编程助手打开项目文件夹，再发送下面的提示词。使用普通聊天 AI 时，请补充自己的操作系统和解压路径，由它逐步指导你操作；普通聊天窗口不能直接替你安装软件或启动电脑上的服务。

```text

   检查是否存在影响本地模式的环境变量，但不要输出密钥内容。

   以及哪些步骤已经验证、哪些仍需要我确认。
```

**第三步：打开网站并开始使用**

启动成功后，打开终端显示的地址，通常为 [http://localhost:3000](http://localhost:3000)。终端窗口需要保持运行，按 `Ctrl+C` 停止。下次使用时，在 `oshitrip/` 目录运行 `pnpm dev` 即可；Windows PowerShell 可用 `pnpm.cmd dev`。

想使用生产模式运行，可以在安装依赖后执行：

```sh
pnpm build
pnpm start
```

等待构建成功后再启动；使用生产模式后，修改代码需要重新构建。

**源码版更新**：先停止正在运行的服务。通过 Git 下载且没有未提交改动时，可在仓库根目录运行 `git pull --ff-only`；如有本地修改或分支分歧，先保留修改并处理差异，不要直接覆盖。通过 ZIP 下载时，将最新源码解压到新文件夹，按需迁移自己的 `.env.local` 配置，不复制旧的 `node_modules` 或 `.next`。随后在 `oshitrip/` 重新运行 `pnpm install --frozen-lockfile`，开发模式运行 `pnpm dev`，生产模式依次运行 `pnpm build`、`pnpm start`。继续使用原浏览器和原访问地址才能读取原收藏。

**本地版使用说明**

- 从源码默认启动时，活动资料随项目提供；如需与 Windows 版相同的自动更新，可按[应用配置](oshitrip/README.md)开启统一数据模式。没有近期活动时，可检查筛选条件和“包含历史活动”选项。
- 关注、收藏和旅行安排保存在当前浏览器中，换设备、换访问地址或清理浏览器数据后不会自动同步。
- 默认本地模式适合查询和规划；数据库管理功能及自动采集需要另外配置，不影响本地启动。

- [应用配置与常用命令](oshitrip/README.md)

GitHub Actions 配置位于仓库根目录的 `.github/workflows/`。使用 Vercel 部署时，将应用 Root Directory 设置为 `oshitrip`。
