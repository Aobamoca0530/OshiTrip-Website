# OshiTrip 🧳✨

让每一次跑活，都能多遇见一点喜欢。

OshiTrip 是一个面向日本 IP 联动活动与跑活旅行的查询网站。你可以根据自己的出行日期、停留城市和喜欢的 IP，筛选旅途中可以顺便参加的活动，把想去的地方加入旅行备选。

## 💭 为什么做这个网站

每次计划去日本跑活，我都会花很多时间翻官方 SNS。活动消息大多通过社交平台发布，联动咖啡、快闪店、展览、Live 和周边贩售的信息散落在不同账号和公告里，想整理出一份完整的行程并不方便。

看到感兴趣的活动后，往往还要继续查：活动在哪家店举办？我去的那几天还在不在？能直接入场，还是需要提前预约或参加抽选？不同门店的举办时间和参加规则是不是一样？

这些信息有时藏在长长的公告里，有时写在宣传图上，还有一些需要跳转到其他页面才能确认。等到好不容易查清楚，才发现活动和自己的行程对不上，或者已经错过了预约时间。

所以，我做了 OshiTrip，希望把散落的活动信息整理到一起，让跑活前的准备更方便。

## 🗺️ 它能帮你做什么

- **根据行程找活动**：按各个城市的停留日期匹配活动门店，看看旅途中有哪些可以顺路参加的活动。
- **围绕喜欢的 IP 筛选**：查找感兴趣的作品、企划和乐队相关活动，关注 IP、收藏想去的活动。
- **查看参加方式和预约信息**：集中查看举办时间、地点、预约或抽选安排，并通过官方链接确认具体规则。
- **整理旅行备选**：把感兴趣的活动放进行程备选，结合自己的私人安排规划跑活路线。
- **查询 Live 抽选关联商品**：了解附券商品、抽选时间和店铺特典，方便一起做出行准备。
- **自动发现公告与商品图**：在“官方新消息”查看自动采集的快闪、联动公告，以及现场售卖商品、菜单和特典图片。

比如，已经决定某几天在东京、之后去大阪，就可以按这段行程寻找同期举办的联动活动，再确认哪些需要提前预约、哪些适合安排在空闲时间。

## 💖 希望带来的改变

做这个网站的初衷很简单：少花一些时间反复翻 SNS、找公告和核对日期，多留一些时间给真正想参加的活动。

希望 OshiTrip 能帮你在已经确定的旅行里，找到那些“原来这次也能顺便去”的惊喜。

## 🛠️ 本地运行

### 🪟 Windows 双击启动版

不想安装开发环境，可以从 [1.5.0 Release](https://github.com/Aobamoca0530/OshiTrip-Website/releases/tag/v1.5.0-windows) 下载 **OshiTrip-1.5.0-windows-x64.zip**。

1. 将整个压缩包解压到可写文件夹。
2. 双击 **OshiTrip.exe**，等待浏览器自动打开。
3. 保持启动器运行；关闭窗口或点击「停止并退出」即可停止服务。

适用于 Windows 10/11 x64，内置 Node.js，使用系统自带的 .NET Framework。请保留 EXE 旁边的文件夹，不要只复制 EXE，也不要直接在压缩包里运行。当前版本尚未进行代码签名。

收藏和行程保存在当前浏览器中。启动器会记住访问地址；若端口临时被占用，会提示临时地址，待原端口空闲后再次启动会回到原地址。

🔄 **活动数据自动更新**：启动时后台检查统一活动资料，页面顶部显示资料发布时间，也可点击「刷新活动数据」。更新失败或断网时继续使用缓存；首次离线启动使用内置资料。官方图片、地图与外部链接需要联网。活动资料缓存位于 `%LOCALAPPDATA%\OshiTrip\data`，与收藏、行程分开保存。

活动、商品、门店和新公告更新无需重新下载 EXE；软件功能升级仍需下载新版。1.2.0 起支持“官方新消息”和自动收集的商品图片；更早版本建议换用最新启动包。保留原浏览器和访问地址即可继续读取原有收藏。1.1.0 的旧数据源仍保留兼容。

1.5.0 将官方消息分为 Live 与线下活动合集，新公告进入发现活动待审核区。维护者可配置百炼、DeepSeek 或 OpenAI，分别用于翻译和审核；使用 EXE 无需密钥。配置位置与步骤见 [AI 接口配置](oshitrip/README.md#每日自动采集)，统一维护命令和模型数据契约见 [官方消息工作流程](oshitrip/docs/official-news-workflow.md)。

### 📝 统一活动数据怎么维护

维护者核对官方公告后修改活动、商品或门店源文件，运行发布命令生成统一数据包，再提交到本仓库的 `main` 分支。客户端下次启动或手动刷新时即可获取，无需给每位用户单独发文件。发布新资料不需要重新打包 EXE。

也可以把官方活动链接交给 AI，要求它核实日期、城市、预约规则、来源与核实时间，按现有结构更新源文件并完成校验后提交。未知内容保留未知，不根据图片或标题猜测预约规则。

具体文件和命令见 [统一数据发布步骤](oshitrip/README.md#统一数据发布步骤)。这里的自动更新是同步维护者发布的资料，并非实时抓取 SNS、库存或预约空位。

### 🤖 自动采集官方公告和商品图片

本仓库的 GitHub Actions 每天北京时间 **09:17** 检查 BanG Dream! 新闻及 Live 目录、虹咲、少女歌剧官网、Bushiroad Creative 和 SWEETS PARADISE。流程为：官方公告 → 企划与线下活动筛选 → 中文介绍和参与规则 → 官方图片 → 发现活动。电脑不必一直开着；客户端启动或刷新即可获取。调度可能延迟，覆盖范围不代表所有活动。

Bushiroad Creative、SWEETS PARADISE 按企划白名单筛选：目前关注 **BanG Dream!（含旗下乐队）、Love Live!（含虹咲）、少女歌剧**，不收录其他企划的单独公告。关键词可在 `oshitrip/scripts/crawler/project-keywords.json` 维护；目录与公告标题都会检查，已有无关记录也会清理。

纯网售、广播配信和一般商品宣传会被过滤，线下快闪、展览、联动与 Live 保留。**发现活动中的 Live 合集**集中展示巡演和现场演出，每一站分别记录场地、日期及抽选规则。“抽选资格公布”不等于“报名开放”，未公布的期限留空。

中文规则附日文依据；只有日期、场地与规则证据通过校验的记录才进入行程匹配，信息不全的显示为“待补全”。图片分为**售卖商品、特典 / 满赠、餐饮菜单、宣传图**。图片机器译文单独标注待核实，不用于推断报名状态、价格或库存。

图片引用官方地址，不批量转载托管；离线可看文字资料，图片需联网。[虹咲公式X](https://x.com/Nijigaku_movie) 是官方账号入口，目前未自动同步帖子、不采集 X 登录内容。采集失败时保留此前资料，运行报告可在 Actions 中查看。

维护者在仓库 Actions Secrets 配置 `DASHSCOPE_API_KEY` 后启用自动中文整理：正文使用 `qwen-plus`，每轮最多 24 篇变化的公告；图片规则使用 `qwen3-vl-plus`，最多 4 次新识别。调用会使用维护者的百炼额度；普通用户无需密钥。没有密钥时仍采集、筛选和更新现有资料，待译公告明确标注“待翻译”，不会伪造译文。未变化的正文和已识别的图片复用结果。

旧版刷新仍可获得兼容的活动资料；中文公告、图片规则译文和 Live 合集需要升级到 1.4.0。原有收藏和行程继续保存在原浏览器中。

### 从源码运行

应用源码位于 `oshitrip/`，需要 Node.js 24 与 pnpm 11.25.0。

```sh
cd oshitrip
pnpm install --frozen-lockfile
pnpm dev
```

默认使用本地活动资料，无需配置数据库账号即可运行。

### 🤖 AI 辅助本地部署（新手推荐）

想在自己的电脑上使用 OshiTrip，可以让 AI 帮你完成环境检查和启动。这里运行的是本地版，通过浏览器访问；无需购买服务器，也无需配置数据库或 AI API Key。首次安装依赖需要联网，官方图片、地图和外部链接也需要网络。

**第一步：下载项目**

在本仓库页面选择 **Code → Download ZIP**，解压到自己方便找到的位置；如果已经安装 Git，也可以运行：

```sh
git clone https://github.com/Aobamoca0530/OshiTrip-Website.git
```

下载后，打开项目最外层文件夹。真正的应用目录是里面的 `oshitrip/`，其中应有 `package.json` 和 `pnpm-lock.yaml`。

**第二步：把下面这段话复制给 AI**

让能访问本地文件和终端的 AI 编程助手打开项目文件夹，再发送下面的提示词。使用普通聊天 AI 时，请补充自己的操作系统和解压路径，由它逐步指导你操作；普通聊天窗口不能直接替你安装软件或启动电脑上的服务。

```text

仓库：https://github.com/Aobamoca0530/OshiTrip-Website

   应用目录是 oshitrip/，不要使用文档作者电脑上的固定路径。
2. 检查 Node.js、npm 和 pnpm。按项目说明使用 Node.js 24，
   并核对 packageManager 中固定的 pnpm 版本（目前为 11.25.0）。
   缺少环境时，使用官方安装方式，说明需要我手动完成的步骤。
   Windows PowerShell 中可使用 npm.cmd 和 pnpm.cmd。
3. 使用默认本地资料模式。不需要配置 Supabase、爬虫或 AI 服务。
   检查是否存在影响本地模式的环境变量，但不要输出密钥内容。
   NEXT_PUBLIC_SUPABASE_URL 和 NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY
   均应未设置或为空；若已有配置，先说明影响并保留原配置。
4. 在 oshitrip/ 中运行 pnpm install --frozen-lockfile，
   然后运行 pnpm dev。不要为绕过安装错误删除锁文件或擅自升级依赖。
5. 查看启动日志，把实际可访问的本地地址告诉我。
   默认端口通常是 3000；如被占用，使用空闲端口，

   以及哪些步骤已经验证、哪些仍需要我确认。

```

**第三步：打开网站并开始使用**

启动成功后，打开终端显示的地址，通常为 [http://localhost:3000](http://localhost:3000)。终端窗口需要保持运行，按 `Ctrl+C` 停止。下次使用时，在 `oshitrip/` 目录运行 `pnpm dev` 即可；Windows PowerShell 可用 `pnpm.cmd dev`。

想使用生产模式运行，可以在安装依赖后执行：

```sh
pnpm build
pnpm start
```

等待构建成功后再启动；使用生产模式后，修改代码需要重新构建。

**本地版使用说明**

- 从源码默认启动时，活动资料随项目提供；如需与 Windows 版相同的自动更新，可按[应用配置](oshitrip/README.md)开启统一数据模式。没有近期活动时，可检查筛选条件和“包含历史活动”选项。
- 关注、收藏和旅行安排保存在当前浏览器中，换设备、换访问地址或清理浏览器数据后不会自动同步。
- 默认本地模式适合查询和规划；数据库管理功能及自动采集需要另外配置，不影响本地启动。

- [应用配置与常用命令](oshitrip/README.md)

GitHub Actions 配置位于仓库根目录的 `.github/workflows/`。使用 Vercel 部署时，将应用 Root Directory 设置为 `oshitrip`。
